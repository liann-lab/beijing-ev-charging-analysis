# Figshare Version 2：重新启动分析

## 版本区别

旧数据来自同一数据集的早期发布，站点文件是月度汇总；新数据按用户在Figshare Version 2页面下载的文件核验。注意：发布方Version 2与本项目此前“第二版清洗”是两个不同概念，不能混称。

- 新订单有 `transaction_date`、`station_id`、`pile_id`、`rated_gun_power_kw`。
- 新站点表 `stations_public.parquet` 有8,553行和站点、场所、网格、设施数量等属性，不是月表。
- 新旧订单行数相同。逐批按对应行核对，开始时间、结束时间、功率和电量全部一致。日期字段并非简单改名：1月345,059条、7月1,888,155条的日期值与旧 `dating_time` 不同。
- 新版仍有1月20条极端电量、1,179条设备类型及功率缺失；7月仍有13,493条6月开始的订单。不能把旧版全部异常归因于版本差异。

## 参考论文的重启流程

1. 完成版本与字段核验、原文件SHA-256记录、全量异常扫描以及站点关联校验。详见 `release_v2_audit.json`。
2. 独立生成发布版v2的清洗结果，不覆盖旧版。保留来源行、异常标记和剔除原因，按开始月归属整笔订单。
3. 将保留订单通过唯一 `station_id` 连接站点属性，以同一批订单重新汇总站点月表、网格订单量和电量。旧“无法关联”的限制不再直接沿用。
4. 参考论文PDF第15页，以月会话时长总和除以枪数、每日24小时和月份天数估算利用率。说明静态枪数和整月可用假设，不把连接时长等同有效充电时长；按开始月整笔归属也不同于跨月分摊占用时长。
5. 重画整体与空间图，两个月统一色标；检查不足5笔订单或不足5把枪的图表筛选，并保留完整汇总，说明筛选原因。
6. 构造共同网格样本，再进行冬夏两个观察月的需求与利用差异比较。

## 论文规则不能无条件照搬

论文第10—12页描述了时间、负值、缺失、长时长、高电量（非公交200 kWh）和分组Z分数筛查，并称部分记录已在发布前剔除。但新版仍出现超过200 kWh的记录，需保留核查证据；站点类别也需先核对编码。论文中的唯一交易标识未在公开字段中提供，`pile_id` 是桩编号而不是交易编号，不能据此去重。Z分数在长尾分布中也不应直接被当作记录错误的证明。

当前已确认可复用的项目规则是缺失字段剔除、1000 kWh与容量不符的联合规则，及开始月归属；其余筛查先标记并做敏感性比较。不会声称完整复现作者上游清洗。
